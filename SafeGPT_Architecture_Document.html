1. Executive Architectural Overview

SafeGPT introduces an intelligent, zero-cloud privacy perimeter around Large Language Models. When users ask questions containing sensitive personal identifiers (Aadhaar, PAN, phone numbers, person names, and addresses), SafeGPT executes a deterministic, cryptographically authenticated 5-stage pipeline: Detect → Mask → Encrypt → Local Inference → Restore.

3. Model Governance: Federated Learning & Differential Privacy

For multi-institutional collaborative training without centralizing sensitive records (e.g., Hospital A, B, and C), SafeGPT integrates Federated Averaging (FedAvg) with a formal Gaussian Differential Privacy (DP) engine.

Hospital Node A (Edge) 300 private records
Local SGD training
Hospital Node B (Edge) 200 private records
Local SGD training
Hospital Node C (Edge) 150 private records
Local SGD training
↓ Local Model Weight Updates
Differential Privacy Engine (dp_filter/noise_engine.py) & Federated Aggregator (federated/) Bounded DP-FedAvg
• L2 Gradient Clipping: Bounds individual client influence to clipping threshold \(C = 1.0\).
• Gaussian Perturbation: Injects calibrated noise \(\mathcal{N}(0, \sigma^2)\) parameterized by privacy budget \((\epsilon, \delta)\).
• FedAvg Server: Aggregates clipped, noisy updates across communication rounds without inspecting client data.

5. Spoken Walkthrough Script (For Your Presentation)

1. Introduction: "Mam, SafeGPT is an on-premise, privacy-preserving conversational AI framework. When a user asks a query containing sensitive data—like Aadhaar or name—the prompt never travels directly to an AI model."

2. Detection & Masking: "Our Hybrid PII Detection Engine uses deterministic Regex for Indian Aadhaar and PAN, contextual rules for DOB and Passport, and spaCy NER for names and locations. It achieved 100% Recall with 0 False Negatives on our 240-example benchmark. Sensitive entities are instantly replaced with typed tokens like [PERSON] and [AADHAAR]."

3. Cryptographic Storage: "The mapping dictionary is encrypted using AES-256-GCM with a 96-bit nonce and stored in encrypted_mapping.bin. Zero plaintext PII is ever written to disk."

4. Local Air-Gapped Llama 3: "The sanitized prompt is sent to local Llama 3 (8B) via Ollama. 0 KB is sent over the internet. When the model responds, our de-masker performs in-memory decryption and restores placeholders back to original values."

5. Federated Governance: "Finally, for collaborative institutional training, we use Federated Averaging (FedAvg) combined with a Gaussian Differential Privacy engine (L2 clipping and noise addition) to mathematically bound individual data leakage."
